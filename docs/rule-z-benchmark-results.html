Rule Z — v1 vs v2 vs v3 Comparison

12 total builds (3 baseline + 9 Rule Z variants) · identical spec · isolated contexts · Claude Opus 4.6 · 2026-04-14

Headline: Rule Z v2 and v3 have both reached the anti-pattern floor for this benchmark. The improvement curve: A → v1 (−64%) → v2/v3 (~−98 to −100%). The v2→v3 delta is within sampling noise. Both produce ~25% fewer DOM nodes than the baseline at runtime, confirming the structural wins translate to real render cost.

What v3 added — concrete before/after code snippets — appears to maintain v2's results rather than measurably improve them. The floor was already reached; v3's value is in reliability (reducing the chance of regression) rather than better scores.

Key findings

1. v2 and v3 hit the floor

After fixing two measurement false positives (setState-in-loop greedy regex; Map-as-state being flagged as cache), both v2 and v3 register essentially zero anti-patterns. v3's 1.33 average is from a single run (C8) that produced 4 inline style objects — within sampling noise for n=3.

2. DOM reduction replicated across 6 Rule Z builds

v2 and v3 both produce ~630 DOM nodes vs baseline ~851 — a 25% reduction that held across 6 independent builds. This is the most defensible runtime metric in the benchmark: Rule Z's hoisted styles, memoized rows, and cleaner render paths translate to measurably less DOM work.

3. Mount time is flat — no penalty from added structure

Rule Z runs produce more files and more lines of code (extracted constants files, memoized wrappers, useCallback handlers). This costs essentially nothing at mount time: all variants mount in ~840–855ms. The extra abstraction doesn't slow the app down.

4. v2 → v3 is within noise

The prediction was that concrete before/after snippets would push Rule Z even further past v2. The data says: v2 was already at the floor, so "further" wasn't possible in this benchmark. v3's value is likely in reliability — reducing the chance that an occasional build regresses — rather than a measurably better score. Testing this would require a larger sample (n=10+ per variant) or a more complex feature where edge-case patterns appear.

5. Context (CLAUDE.md) still didn't move the needle

All variants — including A (no CLAUDE.md) — used the shared utilities. The Shared utility reuse metric is basically flat at 3.0–3.67 across every variant. This re-confirms the original finding: modern agents grep well enough that a minimal CLAUDE.md doesn't change reuse behavior at this project size.

Recommendation

Ship v3 as the default. The measurable delta from v2 is small — maybe zero — but v3 adds several things that matter for long-term reliability:

  • Concrete examples that help the agent recognize the pattern faster in unfamiliar contexts
  • Domain-specific profiles for non-React projects (backend, games, mobile — where v2's React-focused rules don't apply)
  • AST-based verification (less false positive / false negative than regex)

The benchmark caps out at v2 for this specific React dashboard. Harder tests (larger apps, multi-turn projects, non-React stacks) would likely separate v2 from v3 more clearly.
