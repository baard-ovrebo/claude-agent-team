TL;DR

Context engineering did not matter in this benchmark. Every variant (including A — no context) found and reused the shared utilities by grepping the codebase. Vesa's underlying thesis — "modern agents grep well enough" — is strongly supported.

Rule Z produced a clear, measurable reduction in render-time allocation patterns. Inline object literals in JSX dropped 61% (A→C), inline arrow functions in JSX dropped 89%, total anti-patterns dropped 60%.

My on-the-record prediction was partly wrong. I predicted B would close most of the “didn't know” gap — but there was no gap to close. I predicted the C-B delta would be smaller than A-B — it was actually larger. The patterns Rule Z catches are not the ones context can close.

Finding 1 — Context engineering didn't matter for structural reuse

Vesa was right

All 3 A-variant runs (no CLAUDE.md, no hints at all) used the shared formatDueDate and apiCall utilities. Nobody reimplemented a date formatter. Nobody wrote a raw fetch(). Reuse hits were identical between A (no context) and B (minimal map): 3.0 each.

The minimal CLAUDE.md I planned to push as a Rule Z prerequisite would have had zero measurable effect on this benchmark. Agents grep'd the base repo on their own and found what they needed. Modern agents grep faster than they parse docs.

Finding 2 — Rule Z produced real reductions in “lazy default” patterns

Render-time allocation patterns collapsed under Rule Z

In all 3 A-variant and 3 B-variant runs, agents produced 55–70 inline object allocations per build (mostly style={{...}} re-created every render) and 5–7 inline arrow functions in JSX props (breaks React.memo).

Under Rule Z, those collapsed to 21 inline objects and <1 arrow function on average, because the agents proactively hoisted styles to module scope constants and bound event handlers via useCallback instead of inline arrows.

This is the “AI knew but reached for the lazy option anyway” failure mode — context engineering can't fix it because there's nothing missing to learn.

Finding 3 — Rule Z induced architectural improvements too

All 3 C runs used React.memo + useMemo + useCallback + stable refs

Every C-variant run independently produced:

  • A userId → name Map memoized via useMemo (O(1) per row vs users.find() O(n·m))
  • A Set<string> for selection state (O(1) toggle vs array-includes)
  • TaskRow wrapped in React.memo with stable useCallback handlers
  • Module-scope style constants instead of inline style={{...}}
  • Stale-response guards (mountedRef + sequence counters) for async races
  • A separate constants.ts file for magic values
  • A QUALITY_AUDIT.md listing every choice and its rationale

None of the A or B runs included any of these patterns, even though the agents had the same model and nearly identical feature spec.

The honest revision: context engineering and Rule Z target non-overlapping failure modes. Context helps when the AI doesn't know something exists. Rule Z helps when the AI knows but picks the lazy option. In this benchmark, the former didn't matter because agents grep'd on their own — the entire measurable improvement came from the latter.

Limitations

  • setState_in_loop false positive. My heuristic caught functional setState inside .map() in optimistic bulk-update code. That's actually the correct pattern — the measurement script over-flags it. C variants had more of these because they wrote more sophisticated optimistic-update logic. Fixing this would narrow the noise further.
  • Single-session scope. This is one feature, one codebase, one day. Bigger apps with deeper utility surfaces could change the context picture — a CLAUDE.md might actually help when agents would otherwise miss something in a 500-file repo.
  • Same base model. All 9 runs used the same Claude version. Different models (Sonnet vs Opus, different vendors) may show different ratios.
  • No runtime benchmark. The measurements are structural, not performance. Actually running the 3 versions and measuring FPS, memory, render count under load would be the next step.

Conclusion

The revised synthesis that came out of this:

Minimal structural context (Vesa's 2-line map) had zero measurable effect in this benchmark — agents grep'd on their own. I'd still ship it for bigger repos where grep surface area explodes, but it's not load-bearing for small-to-medium projects.

Rule Z produced a clear 60% reduction in render-allocation anti-patterns — the category context can't address because the information isn't missing, the discipline is.

Combined story: minimal context + hard quality walls + free exploration between. The quality walls are doing the heavy lifting, not the context layer. That's the opposite of what I'd assumed going in.
